# Supabase setup for SCV2 (orders + products)

Use Supabase for orders and optionally for the product catalog. No VM to manage; Supabase hosts Postgres and gives you a dashboard.

## 1. Create a Supabase project

1. Go to [supabase.com](https://supabase.com) and create a project.
2. In **Settings → API**: copy **Project URL** and **service_role** key (secret).

## 2. Create tables

In Supabase **SQL Editor**, run the full SQL in **supabase/schema.sql** (creates `orders`, `order_items`, and optionally `products`).

Or run this:

```sql
create table if not exists public.orders (
  id bigint generated by default as identity primary key,
  status text not null default 'pending' check (status in ('pending', 'paid', 'cancelled')),
  total numeric(10,2) not null,
  currency text default 'USD',
  date_created timestamptz default now(),
  paypal_order_id text
);

create table if not exists public.order_items (
  id bigint generated by default as identity primary key,
  order_id bigint not null references public.orders(id) on delete cascade,
  sku text not null,
  name text not null,
  quantity int not null default 1,
  price numeric(10,2) not null
);

create index if not exists order_items_order_id_idx on public.order_items(order_id);

alter table public.orders enable row level security;
alter table public.order_items enable row level security;
create policy "Service role full access orders" on public.orders for all using (true) with check (true);
create policy "Service role full access order_items" on public.order_items for all using (true) with check (true);
```

## 3. Env vars

In **.env.local** and **Vercel** (Settings → Environment Variables):

| Variable | Value |
|----------|--------|
| **NEXT_PUBLIC_SUPABASE_URL** | Your project URL (e.g. `https://xxxx.supabase.co`) |
| **SUPABASE_SERVICE_ROLE_KEY** | The **service_role** key from Supabase (Settings → API) |

If both are set, the app uses Supabase for checkout/orders and **/admin** redirects to Supabase Studio. You can leave Directus vars unset.

## 4. Admin

Open **/admin** on your site → you’re redirected to **Supabase Studio** (Table Editor, SQL, etc.). Or go to [app.supabase.com](https://app.supabase.com) and open your project.

No token needed for the app: the server uses **SUPABASE_SERVICE_ROLE_KEY** for all order operations.

## 5. Adding products (optional)

If the **products** table exists and has rows, the **store** and **product pages** use Supabase as the catalog instead of the built-in list.

1. In Supabase Studio, open **Table Editor** → **products**.
2. Click **Insert row** and fill:
   - **slug** (required, unique) – URL slug, e.g. `my-product-123`
   - **sku** (required) – e.g. `SKU-001`
   - **name** (required)
   - **price** (required, number) – e.g. `29.99`
   - **category** – e.g. `Best Seller`, `Women's Health`, `Weight Loss`
   - **short_description** (optional)
   - **description** (optional)
   - **image** (optional) – main image URL, e.g. `/images/products/SKU-001/01.png`
   - **images** (optional) – JSON array of image URLs, e.g. `["/images/products/SKU-001/01.png", "/images/products/SKU-001/02.png"]`
   - **sort_order** (optional) – lower numbers show first on the store (default 0)
3. Save. New rows appear on **/store** and at **/product/[slug]**.

If **products** is empty or the table doesn’t exist, the site uses the built-in product list as before.

### Import all existing products (one-time)

To copy every product from the built-in catalog into Supabase so the dashboard becomes the source of truth:

1. Create the **products** table in Supabase (SQL above or full `supabase/schema.sql`).
2. In SCV2, ensure `.env.local` has **NEXT_PUBLIC_SUPABASE_URL** and **SUPABASE_SERVICE_ROLE_KEY**.
3. From the **SCV2** directory run:
   ```bash
   npm run import-products-to-supabase
   ```
   This reads the built-in product list (including overlays from `products-from-site.json`) and upserts every product into the **products** table by **slug**. You can run it again to update existing rows.
